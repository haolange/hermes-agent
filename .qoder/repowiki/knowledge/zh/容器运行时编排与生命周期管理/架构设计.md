- **核心架构**：采用 s6-overlay v3 的 `Architecture B` 模式，以 `/init` 为 PID 1，通过 `main-wrapper.sh` 作为主程序处理用户 CMD，同时利用 `s6-rc.d` 定义长期运行的后台服务（如 dashboard）。
- **初始化流程**：分为两个阶段。第一阶段由 `stage2-hook.sh`（挂载于 `cont-init.d/01-hermes-setup`）执行 root 级引导，包括 UID/GID 动态重映射、数据卷所有权修复、配置种子生成及技能同步；第二阶段由 `02-reconcile-profiles` 触发 Python 引导脚本，根据持久化状态恢复各 Profile 的网关服务。
- **权限与安全边界**：实现了严格的特权降级机制。`main-wrapper.sh` 和 `dashboard/run` 均通过 `s6-setuidgid hermes` 将运行态进程降权至非 root 用户；`hermes-exec-shim.sh` 拦截 `docker exec` 调用，自动将 root 身份的操作降权至 hermes 用户，防止配置文件被意外锁定。
- **服务监督体系**：通过 `cont-init.d/015-supervise-perms` 修正 s6 监督目录的所有权，确保非 root 用户可使用 `s6-svc` 等工具进行生命周期控制；`dashboard` 服务通过 `finish` 脚本配合退出码 125 实现条件性禁用（当环境变量未开启时永久停止而非重启）。
