Gateway 采用三层协作：gateway_runtime（config/platform_registry/delivery/slash_commands/hooks）负责进程启动、配置校验、平台适配器动态注册与命令路由；session_lifecycle（session/session_context/session_state/turn_context/turn_lease）在每条入站消息上创建 SessionContext 并绑定到 PlatformAdapter，管理会话持久化索引、转轮上下文与跨进程租约；streaming_dispatch（stream_consumer/stream_dispatch/stream_events/streaming_tts_consumer）消费 agent 工作线程产出的结构化流事件，经 relay.transport/adapter 桥接到各平台的 send_or_update_status 能力实现渐进式编辑。run.py 作为单一入口串联三者：先初始化 config 与 platform_registry，再拉起各平台 adapter 的 HTTP/Webhook/Polling 循环，所有 inbound 事件通过 delivery.DeliveryRouter 路由到对应 session，再由 streaming_dispatch 把 agent 输出回灌到原 chat_id。共享边界集中在 platforms/base.py 的 PlatformAdapter 抽象、relay 层的 descriptor/command_manifest 以及 gateway/session 暴露的 SessionStore 接口。
