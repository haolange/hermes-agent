本模块是 gateway 包顶层的“横切”支撑层，不直接实现具体平台适配器，而是为各 platform/* 适配器与上层 run.py 提供共享基础设施，按职责拆分为若干独立文件：
- 配置与枚举：`config.py` 定义 `Platform` 枚举（含 `_missing_` 动态成员以支持插件平台）、`GatewayConfig` / `PlatformConfig` / `SessionResetPolicy` / `StreamingConfig` 等 dataclass，并通过 `_PLATFORM_CONNECTED_CHECKERS` 映射表集中声明各平台的连通性判定逻辑；`platform_registry.py` 通过 `PlatformRegistry` 单例 + 延迟加载（`register_deferred`）机制让插件平台自注册，避免启动时导入所有重依赖 SDK。
- 投递路由：`delivery.py` 中的 `DeliveryRouter` / `DeliveryTarget` 解析目标字符串（origin/local/platform:chat[:thread]），经 `resolve_delivery_transport` 优先走原生适配器、回退到 RELAY 适配器，并内置静默叙述过滤、死目标缓存（`DeadTargetRegistry`）、Telegram 私有主题自动创建等跨平台通用逻辑。
- 状态与生命周期：`status.py` 维护 PID 文件、运行时锁（`gateway.lock`）、`gateway_state.json` 运行态快照、respawn-storm 日志，并提供跨平台进程探测（psutil → /proc → ps fallback）与 `--replace` 接管语义；`systemd_notify.py`、`wake.py`、`shutdown_*`、`restart*`、`code_skew.py`、`cwd_placeholder.py` 等处理 systemd watchdog、进程唤醒、优雅关闭、重启风暴防护、代码版本漂移检测与工作目录占位符。
- 授权与会话侧写：`pairing.py` 的 `PairingStore` 用盐值 SHA-256 存储配对码、1 小时 TTL、每平台最多 3 个待审批、失败 5 次锁定 1 小时，并将批准结果镜像写入对应平台的 `*_ALLOWED_USERS` 环境变量；`mirror.py` 将出站投递以 `delivery-mirror` 记录追加到目标会话的 JSONL/SQLite 转录中。
- 扩展点：`hooks.py` 的 `HookRegistry` 扫描 `~/.hermes/hooks/` 下带 `HOOK.yaml` 的目录，动态 `importlib` 加载 `handler.py`，支持精确事件与 `command:*` 通配匹配，异常被吞掉不阻塞主流程。
- 其他辅助：`channel_directory.py`、`profile_routing.py`、`rich_sent_store.py`、`message_timestamps.py`、`sticker_cache.py`、`agent_cache_pressure.py`、`response_filters.py`、`status_phrases.py`、`lifecycle_ledger.py`、`dead_targets.py`、`drain_control.py`、`memory_monitor.py`、`readiness.py`、`scale_to_zero.py`、`shutdown_flush.py`、`shutdown_forensics.py`、`shutdown_watchdog.py`、`restart_loop_guard.py`、`display_config.py`、`authz_mixin.py`、`cgroup_cleanup.py`、`stream_consumer.py`、`stream_dispatch.py`、`stream_events.py`、`streaming_tts_consumer.py`、`turn_context.py`、`turn_lease.py`、`slash_access.py`、`slash_commands.py`、`session*.py`、`runtime_footer.py`、`whatsapp_identity.py`、`kanban_watchers.py` 等文件各自承担通道目录、多 profile 路由、已发送富消息去重、时间戳追踪、贴纸缓存、内存/缓存压力监控、响应过滤器、就绪探针、零扩缩容、优雅关闭冲刷、系统信息收集、重启循环保护、显示配置、授权混入、cgroup 清理、流式消费分发、TTS 消费、对话上下文/租约、斜杠命令访问控制、会话状态、运行时页脚、WhatsApp 身份归一化、看板观察者等单一职责功能，均通过函数或类暴露给上层调用，彼此之间尽量保持单向依赖（如 delivery → config/platform_registry/dead_targets，pairing → platform_registry）。
