模块由四个文件构成清晰的职责分层：
- `stream_events.py` 定义纯 frozen dataclass 的事件契约（`MessageChunk`/`MessageStop`/`Commentary`/`ToolCallChunk`/`ToolCallFinished`/`LongToolHint`/`GatewayNotice`），仅描述“发生了什么”，不含任何平台或 I/O 逻辑，作为 agent→gateway 的无状态传输层。
- `stream_dispatch.py` 中的 `GatewayEventDispatcher` 是同步调度器，接收上述事件并通过注入的 `BasePlatformAdapter` 钩子（`render_message_event`、`format_tool_event`）把渲染决策交给适配器；它维护 per-channel 的 tool-mode（all/new/verbose/off）、预览长度和去重状态，并支持通过 `on_long_tool`/`on_notice` 回调让 gateway 决定是否展示提示。
- `stream_consumer.py` 中的 `GatewayStreamConsumer` 是核心异步消费者：通过 `queue.Queue` 桥接同步的 `on_delta()`（agent 工作线程）与异步 `run()` 任务，按 `edit_interval`/`buffer_threshold` 节流，使用 edit-in-place（或 Telegram DM 的原生 draft streaming）渐进更新单条消息；内置 think-block 过滤、溢出分片、静默响应抑制、flood-control 退避、fresh-final 替换等复杂状态机。
- `streaming_tts_consumer.py` 中的 `StreamingTTSConsumer` 采用相同模式：同步 `on_delta()` → `SentenceChunker` 切句 → queue → asyncio 任务调用 `StreamingTTSProvider` 合成 PCM 并通过 `StreamingTTSHandle` 写入适配器，支持 abort/finish/idempotent 取消及 whole-file TTS 回退协商。
依赖方向单向：dispatch 依赖 events + adapter；consumer 依赖 platform base + config + response_filters；tts consumer 依赖 platforms.base 的 AudioFormat/StreamingTTSHandle 与 tools.tts_streaming，彼此之间不互相引用。
