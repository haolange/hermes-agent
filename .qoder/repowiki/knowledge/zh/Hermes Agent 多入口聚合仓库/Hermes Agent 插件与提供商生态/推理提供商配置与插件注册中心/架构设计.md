模块由两部分组成：`base.py` 提供声明式的 `ProviderProfile` dataclass（包含身份、端点、认证类型、视觉能力、模型目录、请求级钩子等字段）以及若干可覆写的方法（`get_hostname`、`prepare_messages`、`build_extra_body`、`build_api_kwargs_extras`、`fetch_models`、`default_vision_model`、`get_max_tokens`），作为所有具体提供商插件的基类；`__init__.py` 维护进程内全局 `_REGISTRY`、`_ALIASES` 和 `_PROVIDER_LIST_CACHE`，在首次调用 `get_provider_profile()` / `list_providers()` 时触发 `_discover_providers()`，按顺序扫描三类来源并 import 它们以触发模块级 `register_provider()` 自注册：① 仓库根 `plugins/model-providers/<name>/` 下的 bundled 插件，② `$HERMES_HOME/plugins/model-providers/<name>/` 下的用户插件（同名覆盖 bundled），③ 兼容旧版 `providers/*.py` 单文件模块（通过 `pkgutil.iter_modules`）。注册完成后，下游 `hermes_cli/*`、`agent/*`、`run_agent.py` 仅通过 `get_provider_profile(name)` 获取 profile 并调用其钩子，不直接持有 provider 实现，形成清晰的“声明式 profile + 运行时注册”分层。
