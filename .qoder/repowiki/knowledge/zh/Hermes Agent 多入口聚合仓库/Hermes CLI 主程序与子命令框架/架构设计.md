模块以 `main.py` 为唯一进程入口，采用「极早期快速路径 + argparse 分派」的两阶段启动：先通过 `_startup_fast`、`_early_recovery`、`_apply_profile_override`、`load_hermes_dotenv` 在导入任何第三方库前完成 UTF-8 设置、venv 自愈、profile/HERMES_HOME 选择、.env 加载与安全开关桥接；随后由 `_parser.build_top_level_parser()` 构建顶层 argparse（仅包含 `chat` 子解析器），其余子命令解析器在 `main.py` 中集中 import 并挂载到 `subparsers.add_parser(...)`。

子命令按职责分层组织：
- `subcommands/`：每个文件对应一个 `hermes <cmd>` 子命令，统一暴露 `build_<cmd>_parser` + `cmd_<cmd>` 函数，被 `main.py` 集中注册。
- `dashboard_auth/`：基于 `base.DashboardAuthProvider` 抽象与 `registry.register_provider` 插件机制实现的 Web 仪表盘鉴权框架，内含 cookies、token、native flow、middleware、routes 等实现。
- `observability/`：生命周期事件钩子的内置消费者（relay_shared_metrics、shared_metrics_subscriber），对外暴露 `observe_lifecycle` 钩子入口。
- `proxy/`：基于 aiohttp 的 OpenAI 兼容 HTTP 转发服务器，通过 `adapters/base.UpstreamAdapter` 抽象接入 nous_portal、xai 等上游。
- `web_routers/`：Dashboard 内部 FastAPI/Starlette 路由（cron、git、mcp、profiles、sessions、skills、tools）。
依赖方向单向：`main.py` → subcommands/dashboard_auth/observability/proxy/web_routers，各子包之间不互相引用，仅通过 `hermes_cli.config`、`hermes_logging`、`hermes_constants` 等共享基础设施交互。
