模块按职责拆分为三个文件，均遵循「远端 JSON → frozen dataclass → 表面渲染」的单向依赖：
- `billing_links.py`：维护 `_PROVIDERS` 注册表（slug + base_url host → 计费页面 URL），通过 `build_billing_block` 把错误分类器标记的 `FailoverReason.billing` 转换为带 provider/model/message 的 `BillingBlock`，对 Nous 推理网关走 in-app 路径，第三方 provider 走 deep link。
- `billing_usage.py`：从 NAS `NousPortalAccountInfo.paid_service_access_info` 提取三笔美元数值（subscription_credits_remaining / purchased_credits_remaining / total_usable_credits），经 `usage_model_from_account` 产出 `UsageModel`，包含两条独立 UsageBar（plan 月配额 vs topup 充值），状态按 $5 阈值划分为 free/low/healthy/depleted；`build_usage_model` 通过线程池调用 `hermes_cli.nous_account.get_nous_portal_account_info` 获取数据，并由 `HERMES_DEV_CREDITS_FIXTURE` 环境变量短路到离线 fixture。
- `billing_view.py`：解析 `/api/billing/state` 响应，构造 `BillingState`（含 CardInfo/PaymentMethodInfo/MonthlyCap/AutoReload 等子结构），金额统一用 `decimal.Decimal` 传递并以 `parse_money/format_money` 处理；`build_billing_state` 捕获 `BillingAuthError/BillingError` 降级为 `logged_in=False`，并通过 `HERMES_DEV_BILLING_FIXTURE` 提供多种离线场景；额外提供 `new_idempotency_key()` 和 `validate_charge_amount` 用于充值流程。
依赖方向：本模块仅向上暴露函数/dataclass，向下通过延迟 import 调用 `hermes_cli.*`，自身不持有网络 I/O，所有外部调用被 try/except 包裹实现 fail-open。
