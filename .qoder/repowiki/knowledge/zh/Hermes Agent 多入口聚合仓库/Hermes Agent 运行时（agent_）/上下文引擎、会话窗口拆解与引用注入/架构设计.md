本模块由三个职责正交的文件组成：
- `context_engine.py` 定义 `ContextEngine` ABC（`name`、`update_from_response`、`should_compress`、`compress`、`select_context`、`on_turn_complete`、`get_tool_schemas`/`handle_tool_call`、`on_session_start/end/reset`、`update_model` 等），作为所有上下文压缩插件的统一契约；默认实现通过 `agent.context_compressor` 加载，第三方引擎可通过 `plugins/context_engine/<name>/` 目录或配置 `context.engine` 替换。`sanitize_memory_context` 和 `automatic_compaction_status_message` 是跨引擎共享的边界工具。
- `context_breakdown.py` 是纯展示层：基于 `agent.system_prompt.build_system_prompt_parts` 与 `agent.model_metadata.estimate_messages_tokens_rough` 估算 system prompt、tool definitions、rules、skills、mcp、subagent、memory、conversation 各分类的 token 占用，输出供 CLI `/context` 渲染为 glyph 网格、分类表格及 `compute_context_details` 的 per-skill/per-toolset 明细。
- `context_references.py` 负责在用户消息进入 LLM 前解析 `@kind:value` 引用并展开为内联文本块：`parse_context_references` + 正则匹配 → `preprocess_context_references`(同步) / `preprocess_context_references_async`(并发 `asyncio.gather`) → `_expand_file_reference`/`_expand_folder_reference`/`_expand_git_reference`/`_fetch_url_content`。安全面通过 `_ensure_reference_path_allowed` 调用 `agent.file_safety.get_read_block_error` 统一走凭据黑名单，并对二进制文件以提示块替代直接内联。注入 token 受 context_length 的 25% 软限与 50% 硬限约束，超限则拒绝并标记 `blocked=True`。
依赖方向：`context_breakdown` 与 `context_references` 均只读外部状态（system prompt、model metadata、file safety），不反向依赖 `context_engine`；三者共同被上层 agent 循环在 turn 前后调用。
