本模块由三个并列的运行时入口组成，均通过接收父 `AIAgent` 实例作为首参的方式与上层解耦：
- `conversation_loop.py`：从 `run_agent.AIAgent.run_conversation` 抽离出的约 3900 行主循环，负责一次用户请求的完整生命周期——系统提示恢复、消息克隆与工具调用参数规范化、压缩/重试/回退、上下文窗口估算、最终化 (`finalize_turn`)、后台记忆/技能审查触发等；通过 `_ra()` 懒引用 `run_agent` 以兼容测试期 monkey-patch。
- `moa_loop.py`：为 `/moa` slash command 提供 Mixture-of-Agents 能力，将多个 reference 槽位通过 `ThreadPoolExecutor` 并发扇出（上限 8），每个参考调用经 `_slot_runtime` 解析真实 provider/runtime 并复用 `call_llm`，结果经隐私过滤后交给 aggregator；内置预设/运行时缓存（TTL 300s）、上下文裁剪、工具结果预算截断与中断可取消等待。
- `codex_runtime.py`：两条 Codex 专用路径——`run_codex_app_server_turn` 驱动 `CodexAppServerSession` 子进程并通过 `make_codex_app_server_event_bridge` 把 JSON-RPC `item/started|completed|agentMessage/delta` 事件映射到 Hermes 的 `tool_progress_callback` / `_fire_stream_delta` / `_emit_interim_assistant_message`；`_consume_codex_event_stream` 直接消费 Responses SSE 原始事件流，绕过 SDK 高层封装以避免 `response.output` 漂移导致的崩溃。
依赖方向单向向外：三者仅依赖 `agent.*`、`hermes_*`、`tools.*` 等下层模块，不反向被它们引用；跨文件协作通过 `AIAgent` 属性约定（如 `session_db`、`context_compressor`、`event_callback`）而非显式接口。
