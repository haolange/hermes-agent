模块由三个职责清晰的子文件组成：
- `credential_sources.py` 定义 `RemovalStep`/`RemovalResult` 数据类与全局 `_REGISTRY`，通过 `register()` 在模块导入时集中注册各来源的移除步骤（env、claude_code、hermes_pkce、device_code、qwen-cli、gh_cli、custom_config 等），提供 `find_removal_step(provider, source)` 按 provider/source_id 匹配并执行清理，将原本分散在 `auth_remove_command` 中的 if/elif 分支收敛为可插拔策略。
- `credential_pool.py` 是核心运行时层，定义 `PooledCredential` dataclass（含 `runtime_api_key`/`runtime_base_url` 属性）、`CredentialPool` 类（线程安全 RLock、选择策略 fill_first/round_robin/random/least_used、exhausted/dead 状态机、TTL 冷却、单凭据短冷却），负责从 `hermes_cli.auth` 提供的 auth store 与 config.yaml 中播种、同步外部变更（Claude Code 凭据文件、Codex/xAI OAuth 刷新令牌）、持久化到 `auth.json`，并通过 `_write_through_provider_state_to_global_root` 处理多进程共享 root store 的旋转问题。
- `credential_persistence.py` 位于磁盘边界，维护 `_PERSISTABLE_PROVIDER_SOURCES` 白名单与敏感键集合，提供 `is_borrowed_credential_source` 与 `sanitize_borrowed_credential_payload`，对非 Hermes 拥有的借用型凭证在写入 auth.json 前剥离原始密钥值并保留 SHA256 fingerprint，避免循环依赖 hermes_cli.auth。
依赖方向：pool → persistence（只读脱敏），sources 独立于 pool；三者共同依赖 hermes_cli.auth 与 hermes_cli.config。
