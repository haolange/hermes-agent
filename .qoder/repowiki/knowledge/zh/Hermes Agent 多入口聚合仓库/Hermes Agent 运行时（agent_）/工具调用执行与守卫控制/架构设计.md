模块由三个职责正交的文件组成，构成工具调用的执行管线：
- `tool_executor.py` 是核心入口，提供 `_run_agent_tool_execution_middleware`（串联 relay 重写、hermes 请求/执行中间件、pre-tool-call 插件阻断、guardrails before_call）、`execute_tool_calls_concurrent`（基于 `concurrent.futures` + `threading.Condition` 的有序并发调度器）和 `_ConcurrentToolAuthorizationGate`（序列化审批提示并排除人类等待时间）。它通过 `_ra()` 延迟引用 `run_agent` 以兼容测试 patch，并通过 `agent._tool_guardrails.before_call` 委派守卫决策。
- `tool_dispatch_helpers.py` 是无状态辅助层，负责批量分段规划（`_plan_tool_batch_segments`：按路径读写冲突把 batch 切为 parallel/sequential 段）、多模态结果信封处理、不可信工具输出包裹（`make_tool_result_message` 用 `<untrusted_tool_result>` 标签防御间接 prompt 注入）、文件变更目标提取等。
- `tool_guardrails.py` 是纯函数式守卫控制器 `ToolCallGuardrailController`，维护 per-turn 计数器（精确重复失败、同工具失败、幂等无进展）和 runaway-loop 上限（`web_search`、`delegate_task`），通过 `before_call`/`after_call` 返回 `ToolGuardrailDecision`，不直接修改运行时状态。
依赖方向单向：executor → helpers + guardrails；helpers 仅依赖工具分类与威胁扫描；guardrails 仅依赖配置与结果分类。三者共同被上层 `run_agent` 编排，形成“解析→中间件→守卫→授权→分发→结果封装”的固定流水线。
