三个并列的注册模块（browser_registry.py、image_gen_registry.py、transcription_registry.py）采用相同的内部结构：以模块级 `Dict[str, <Provider>]` + `threading.Lock()` 维护全局注册表，通过 `register_provider`/`list_providers`/`get_provider` 暴露增删查接口，并由 `_reset_for_tests` 供测试清理。
- 依赖方向单向：每个注册表仅依赖对应的 Provider 抽象（`agent.browser_provider.BrowserProvider`、`agent.image_gen_provider.ImageGenProvider`、`agent.transcription_provider.TranscriptionProvider`），由插件在 import 时调用 `PluginContext.register_*_provider` 注入实现。
- 活动 Provider 解析策略因领域而异：
  - 浏览器：显式 `browser.cloud_provider` 优先且忽略可用性；否则按 `_LEGACY_PREFERENCE` 顺序（browser-use → browserbase）遍历并检查 `is_available()`；支持 `local` 短路返回 None 走本地模式。
  - 图像生成：读取 `image_gen.provider` 配置；未设置时回退到“唯一已注册”或遗留的 `fal`；同样对显式配置不检查可用性。
  - 转录：无活动解析函数，仅提供注册表；内置名称集合 `_BUILTIN_NAMES` 在注册阶段拦截冲突，保证内置 STT 处理器始终优先。
- 所有 `is_available()` 调用均通过 `_is_available_safe` 包装捕获异常，防止有缺陷的 Provider 破坏解析流程。
