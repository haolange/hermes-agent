- 通过模块级常量表（如 `_ANTHROPIC_OUTPUT_LIMITS`、`ADAPTIVE_EFFORT_MAP`、`_NON_TOOL_CALLING_PATTERNS`、`_CACHE_POINT_PATTERNS`）集中管理模型能力与行为开关，再以 substring/前缀匹配函数判断具体模型族。
- 对外部 SDK 采用延迟导入 + 缓存模式（`_get_anthropic_sdk`、`_require_boto3`、`_bedrock_runtime_client_cache`），仅在真正调用时才引入重依赖，避免冷启动开销。
- 所有适配器将上游 provider 特有的消息/工具/响应格式转换为统一的 OpenAI 风格 `SimpleNamespace` 对象（choices[].message.content、tool_calls、finish_reason、usage），使上层 agent 循环无需感知后端差异。
- 通过 base_url 主机名/路径匹配函数（`base_url_host_matches`、`_is_third_party_anthropic_endpoint`、`is_native_gemini_base_url`）动态选择认证方式、beta header、重试策略等路径分支，而非硬编码 provider 枚举。
- 对第三方端点的特殊限制（MiniMax 拒绝 tool streaming beta、Azure 需要 api-version 查询参数、Kimi /coding 需要 claude-code UA、DeepSeek 需保留 thinking 块）以专用 `_is_*_endpoint` 判定函数集中处理。
- 错误分类采用专用异常类或辅助函数（`GeminiAPIError`、`is_stale_connection_error`、`is_streaming_access_denied_error`、`is_free_tier_quota_error`、`is_standard_key_auth_error`），将网络/鉴权/配额错误转化为可被上层重试逻辑识别的结构化信号。
