模块由三个职责正交的单文件组成：
- `ssl_guard.py`：启动期前置检查。通过读取 `HERMES_CA_BUNDLE` / `SSL_CERT_FILE` / `REQUESTS_CA_BUNDLE` / `CURL_CA_BUNDLE` 等环境变量与 `certifi.where()` 返回的 bundle，调用 `ssl.create_default_context` + `get_ca_certs()` 验证路径存在、可加载且非空；异常统一包装为 `agent.errors.SSLConfigurationError`，并支持 `HERMES_SKIP_SSL_GUARD` 跳过。
- `ssl_verify.py`：运行时 TLS 参数解析器。按优先级（显式 `ssl_verify: false` → 每 provider 的 `ca_bundle` → 上述四个环境变量 → 默认 `True`）生成 httpx 的 `verify` 值（`False`、`True` 或 `ssl.SSLContext`），并在禁用验证时记录警告日志。
- `file_safety.py`：统一的文件访问安全策略层，被 tools 与 ACP shims 共享。核心是三类守卫：(1) 写拒绝清单——基于 `build_write_denied_paths`/`build_write_denied_prefixes` 与 `HERMES_WRITE_SAFE_ROOT` 白名单判断是否允许写入；(2) 读拒绝清单——屏蔽 `.env*`、Hermes 凭据存储（`auth.json`、`.anthropic_oauth.json` 等）、skills `.hub` 缓存及 mcp-tokens 目录；(3) 软守卫——跨 profile 写入检测（`classify_cross_profile_target`）、沙箱镜像路径检测（host-side 形状匹配 `sandboxes/<backend>/<task>/home/.hermes` 与 container-side 前缀匹配），均返回模型可读的警告字符串而非直接阻断。
依赖方向单向向外：本模块仅依赖标准库 `ssl`/`pathlib`/`os` 与本地 `agent.errors`，不反向被 agent 业务逻辑强耦合，所有守卫以纯函数形式暴露供上层工具调用。
