- RPC 处理器统一使用 `from .method_ctx import HandlerRegistry` 的 `@method("..."), @profile_scoped` 装饰器声明，再于导入时自动注册到 `server.dispatch`。
- 所有 I/O 输出走 `transport.Transport` 抽象（`current_transport()` / `bind_transport()`），而非直接写 `sys.stdout`，使 stdio 与 WebSocket 共用同一分发逻辑。
- 长耗时 RPC（billing、subscription、shell.exec、slash.exec、session.compress 等）显式列入 `_LONG_HANDLERS` 集合，交由 `ThreadPoolExecutor` 执行以避免阻塞 stdin/WS 读循环。
- 跨进程/跨线程资源通过 `threading.Lock` / `RLock` 保护共享状态（`_stdout_lock`、`_cfg_lock`、`_sessions_lock`、`_prompt_lock`、`_session_resume_lock`），并在 finally/atexit 中释放。
- 子进程（`_SlashWorker`、`slash_worker.py`）采用 JSON-lines 协议 + 守护线程 drain stdout/stderr，并通过 `start_new_session=True` 隔离进程组防止被 MCP 清理误杀。
- 错误路径统一落盘：未处理异常写入 `~/.hermes/logs/tui_gateway_crash.log`，信号/退出原因写入同一日志并通过 stderr 前缀 `[gateway-crash]`、`[gateway-exit]`、`[gateway-signal]` 快速定位。
