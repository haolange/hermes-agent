模块以 `server.py` 为核心：维护全局 `_sessions`、`_methods` 注册表、线程池 `_pool`（用于慢 RPC）、`_SlashWorker` 持久子进程以及 session 的创建/恢复/压缩/分支/关闭等完整生命周期；通过 `method_ctx.HandlerRegistry` + `@method(...)` 装饰器将分散在 `methods_session.py`、`methods_config.py`、`methods_prompt.py`、`methods_tools.py`、`methods_complete.py` 中的处理器动态绑定到 `server.dispatch`。

传输层抽象在 `transport.py`：定义 `Transport` Protocol，提供 `StdioTransport`（JSON-RPC over stdio）和 `TeeTransport`（主通道+侧车旁路），并通过 `contextvars.ContextVar` 在当前请求上下文中切换；`entry.py` 是 stdio 入口，循环读取 stdin 调用 `dispatch`；`ws.py` 是 WebSocket 入口，用 `WSTransport` 复用同一 `dispatch`，并对高频 token delta 事件做 coalesce 缓冲与 Nagle 禁用。

进程模型：gateway 主进程通过 `subprocess.Popen` 启动独立的 `slash_worker.py`（`-m tui_gateway.slash_worker`）处理 `/` 斜杠命令，父子进程通过 JSON-lines 管道通信，并带父进程死亡 watchdog 与孤儿回收；MCP 工具发现通过 `hermes_cli.mcp_startup.start_background_mcp_discovery` 在后台线程异步进行，由 `entry.ensure_mcp_discovery_started` / `wait_for_mcp_discovery` 协调。

可靠性：`server._panic_hook` + `threading.excepthook` 写 `tui_gateway_crash.log`；`entry._log_signal` 捕获 SIGTERM/SIGHUP/SIGPIPE 并记录堆栈；`_stdin_recovery.py` 修复共享文件描述符 O_NONBLOCK 导致的假 EOF；`loop_noise.py`、`turn_marker.py`、`synthetic_turn.py` 辅助 TUI 渲染与轮次边界；`project_tree.py`、`git_probe.py`、`render.py`、`host_supervisor.py`、`compute_host.py`、`event_publisher.py`、`slash_fuzzy.py` 提供项目树、Git 探测、渲染、主机监控、事件发布、模糊匹配等横切能力。依赖方向单向：`entry/ws → server → methods_* → transport`，外部通过 `hermes_cli.*`、`agent.*`、`tools.*`、`utils.*` 协作。
