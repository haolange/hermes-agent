本模块按职责拆分为独立子模块，彼此通过显式 import 耦合，无统一入口或框架约束：
- `working_diff.py`：封装 `git diff`/`ls-files`/`--no-index` 调用，暴露 `collect_working_diff(cwd, mode, paths)` 返回统一结构 `{success, stat, diff, untracked}`，被 CLI 与 gateway `/diff` 共享。
- `schema_sanitizer.py`：对 OpenAI-format tool list 的 `parameters` 做深度拷贝并递归清洗（裸字符串 schema、`type` 数组、`anyOf/oneOf` 可空联合、`$ref` 兄弟关键字、顶层组合器、非法属性键），并提供恢复阶段的 `strip_pattern_and_format`、`strip_slash_enum` 作为回退路径。
- `patch_parser.py`：定义 `OperationType`/`PatchOperation`/`Hunk`/`HunkLine` 数据模型，`parse_v4a_patch` 将 V4A 文本解析为操作序列，`apply_v4a_operations` 采用两阶段 validate-then-apply，并通过虚拟 overlay (`pending_content`/`removed_paths`) 保证 MOVE/UPDATE 顺序一致性；实际文件写入委托给外部 `file_ops` 接口以解耦。
- `image_source.py`：单一入口 `resolve_image_source(src, ctx, permitted=("image",))` 统一处理 `data:`/`http(s)`/本地路径/容器路径四种来源，在非本地终端后端下仅允许读取 HERMES_HOME 下的 media cache，其余走沙箱内 exec-read，配合 `SourceUnsafe`/`SourceTooLarge`/`NotAnImage` 等专用异常类型实现安全边界。
- `binary_extensions.py`、`fuzzy_match.py`、`url_safety.py`、`website_policy.py` 等为上述模块提供纯函数式辅助（扩展名白名单、模糊匹配、URL 策略检查）。
依赖方向单向向外：本模块不依赖上层 agent/gateway，仅通过延迟 import（如 `tools.fuzzy_match`、`agent.file_safety`、`tools.terminal_tool`）打破循环依赖。
