本模块由一组相互独立的安全守卫子模块组成，每个文件聚焦一种攻击面：
- `path_security.py`：提供基于 `Path.resolve()` + `relative_to()` 的路径越界校验，被 skill_manager/cronjob/credential 等工具复用。
- `self_repo_guard.py`：通过解析 shell 语法（heredoc、$()、引号作用域）、识别 git/gh/hub/shell 可执行名及参数，递归检查命令是否会改写当前进程驻留的源码 checkout，阻止 `git reset --hard`、`worktree remove`、`stash drop` 等危险操作。
- `tirith_security.py`：以子进程方式调用外部 Rust 二进制 tirith，实现 homograph URL、管道注入、终端注入等内容级威胁扫描；内置自动下载、cosign 签名校验、SHA-256 校验、失败标记持久化、崩溃熔断器（连续 3 次失败后禁用）和 warn-once 去重。
- `threat_patterns.py`：集中维护按 attack class 组织的正则模式集（prompt injection / C2 / exfiltration / persistence），按 scope（all/context/strict）编译并缓存，配合不可见 Unicode 字符检测，供上下文组装与结果分隔系统使用。
- `url_safety.py`：SSRF 防护核心，定义 always-blocked 云元数据 IP/主机白名单、私有网段拦截、CGNAT 阻断，并提供 `is_safe_url`/`async_is_safe_url`、httpx 传输层包装 `_SSRFGuardedNetworkBackend` 在 TCP connect 时二次校验 IP，以及重定向目标提取钩子。
- `website_policy.py`：从 `~/.hermes/config.yaml` 加载用户管理的域名黑名单（支持共享文件、通配符匹配），带 30s TTL 内存缓存。
- `osv_check.py`：在 npx/uvx/pipx 启动 MCP 服务器前查询 Google OSV API，仅阻断 MAL-* 恶意包，带进程内 LRU 缓存。
依赖方向单向向外：各守卫不互相 import，仅依赖 `hermes_constants`、`hermes_cli.config`、`utils` 等基础设施，由上层 tool dispatch 组合调用。
