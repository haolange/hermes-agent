- 安全守卫采用 fail-open 默认策略：网络错误、解析异常或未识别场景返回允许（None/True），仅在明确命中规则时才拒绝。
- 配置读取统一通过 `hermes_cli.config` 或环境变量双通道获取，并以模块级全局变量做进程内缓存（如 `_resolved_path`、`_cached_policy`、`_allow_private_resolved`）。
- 对外部二进制或网络调用的失败进行幂等去重：使用 `warned_messages` set + 锁的 `_warn_once` 或进程内 crash counter + circuit breaker 避免日志风暴与无限重试。
- URL/IP 安全检查分层：always-blocked 云元数据地址（169.254.x.x、metadata.google.internal）在任何开关下均拦截，普通私网地址则受 `security.allow_private_urls` 控制。
- 正则威胁模式以 `(regex, pattern_id, scope)` 三元组集中声明，按 scope 在导入时一次性编译并分发到 all/context/strict 三套索引，运行时只做查找。
- shell/命令解析采用逐词扫描 + 作用域栈（quote、$()、``、括号）+ heredoc 剥离的方式处理转义与嵌套，而非简单 split，以准确识别隐藏的危险子命令。
