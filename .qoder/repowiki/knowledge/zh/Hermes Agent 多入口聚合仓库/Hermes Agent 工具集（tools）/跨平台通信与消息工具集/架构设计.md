本模块由一组独立的工具文件组成，每个文件聚焦一个外部系统或能力，统一通过 `tools.registry.registry.register(...)` 注册到全局工具注册表，供上层 agent 调度。
- 通用消息路由：`send_message_tool.py` 是核心枢纽，解析 `platform:target` 目标字符串，按平台分派到 Telegram、Discord、Matrix、Signal、Feishu、Slack、Weixin、Yuanbao、Email、Ntfy 等路径；优先走运行中 gateway 的 live adapter，回退到插件注册的 `standalone_sender_fn`，再失败则返回错误；同时处理长消息分片、媒体附件（MEDIA: 标签）、caption 合并、cron 重复发送去重以及镜像回写 session。
- 平台专用工具：`discord_tool.py` 直接调用 Discord REST API（`urllib.request`），通过动态检测应用 intents（`/applications/@me`）并缓存到磁盘来裁剪暴露给模型的 action 集合；`feishu_doc_tool.py` / `feishu_drive_tool.py` 共享 thread-local 注入的 lark client，使用 `BaseRequest` 调用飞书文档/评论 API；`homeassistant_tool.py` 通过 aiohttp 访问 HA REST API，对 domain/service 做白名单+正则校验防止 SSRF；`yuanbao_tools.py` 通过 `gateway.platforms.yuanbao.get_active_adapter()` 获取适配器完成群成员查询、贴纸搜索/发送和 DM。
- 桌面 UI 扩展：`react_to_message_tool.py` 在 desktop_ui toolset 下暴露 `react_to_message`，写入 SessionDB 并通过 `desktop_ui.emit('message.reaction')` 实时渲染。
- 依赖方向：所有工具只向上依赖 `tools.registry`、`agent.secret_scope`、`gateway.*`（config/platform_registry/session_context/mirror），不反向被 gateway 导入；各平台 SDK（lark_oapi、python-telegram-bot、aiohttp）均采用运行时 lazy import，避免冷启动开销。
