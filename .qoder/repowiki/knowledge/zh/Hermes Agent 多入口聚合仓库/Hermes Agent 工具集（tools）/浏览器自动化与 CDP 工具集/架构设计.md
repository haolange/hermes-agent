模块以 `browser_tool.py` 作为统一入口，对外暴露 `browser_navigate/snapshot/click/type/...` 等工具函数，内部根据配置与环境在三种后端间路由：(1) 通过 `agent.browser_registry` 插件机制选择的云后端（Browserbase / Browser Use / Firecrawl），由 `_get_cloud_provider()` 自动检测；(2) 本地 headless Chromium，通过子进程调用 `agent-browser` CLI；(3) Camofox REST 后端（`browser_camofox.py`），当设置 `CAMOFOX_URL` 且无 CDP 覆盖时启用。所有后端共享同一套工具签名，并通过 `_is_local_mode()` / `_is_local_backend()` 决定 SSRF 防护策略。

CDP 相关能力独立成两个工具文件：`browser_cdp_tool.py` 提供原始 CDP 命令透传（经 `websockets` 直连 WebSocket），并复用 `browser_tool._eval_ssrf_guard_active` 做私有页面保护；`browser_dialog_tool.py` 仅用于响应 CDP supervisor 捕获的 JS 对话框。

`browser_supervisor.py` 是核心基础设施：每个 `(task_id, cdp_url)` 对启动一个 `CDPSupervisor`，在独立线程内运行 asyncio 事件循环，维护持久 WebSocket 连接，订阅 `Page/Runtime/Target` 事件，注入 JS 桥脚本拦截 `alert/confirm/prompt`，并以 `SupervisorSnapshot` 形式向 `browser_tool` 同步暴露 pending dialogs、frame tree、console 历史。`browser_camofox_state.py` 提供 Camofox 会话身份派生逻辑。

依赖方向单向：`browser_cdp_tool` → `browser_supervisor` → `websockets`；`browser_tool` 反向引用 `browser_supervisor` 仅在需要时延迟导入以避免循环；`browser_camofox` 与 `browser_tool` 之间通过 `CAMOFOX_URL` / `BROWSER_CDP_URL` 优先级约定解耦，不直接互相 import。
