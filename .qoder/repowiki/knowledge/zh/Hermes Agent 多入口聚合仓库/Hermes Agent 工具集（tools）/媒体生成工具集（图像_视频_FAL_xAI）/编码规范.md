- 每个后端工具通过 `registry.register(name=..., toolset=..., schema=..., handler=..., check_fn=...)` 显式声明工具元数据，并在 `check_fn` 中判断凭据/配置可用性以控制工具可见性。
- 对外部 SDK（如 `fal_client`、`httpx`）采用函数内延迟导入，避免模块加载时的冷启动开销，同时保留测试中对模块全局的 monkeypatch 能力。
- 模型/后端能力通过模块级常量或字典集中声明（如 `FAL_MODELS`、`TEXT_TO_VIDEO_SCHEMA`），使用 `supports` / `edit_supports` 白名单过滤负载键，防止向不支持的模型发送未知参数。
- 媒体输入（本地路径/URL/base64）在进入外部服务前统一经由 `resolve_image_source` 或 `_prepare_media` 转换为受管上传引用，并对本地路径做严格识别与长度/格式校验。
- 长耗时异步任务（BFL 视频生成）采用 submit→poll 模式，内部维护预算（`_POLL_BUDGET_SECONDS`、`_CALL_BACKSTOP_SECONDS`）、间隔切片等待与连续传输错误上限，确保可中断且不会无限轮询。
- 错误响应统一序列化为 JSON 字符串并通过 `tool_error` / `error_response` 构造带 `error_type` 的结构化错误，便于上层区分 transport error、provider contract 违规与业务拒绝。
