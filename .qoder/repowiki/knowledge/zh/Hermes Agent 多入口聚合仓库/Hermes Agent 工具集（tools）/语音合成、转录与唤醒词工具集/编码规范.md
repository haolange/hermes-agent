- 所有第三方 SDK 通过 `_import_xxx()` 惰性导入并在失败时静默降级，确保无头/SSH/Docker 环境可正常启动。
- API Key 统一经 `_resolve_provider_key(env_var, provider_id)` 委托给 `tools.tool_backend_helpers.resolve_provider_secret`，遵循 config > env/.env > 凭证池 的解析顺序。
- 用户自定义 provider 通过 `type: command` 声明在 `tts.providers.*` / `stt.providers.*` 下，使用 `{input_path}`、`{output_path}`、`{format}`、`{voice}`、`{model}` 等占位符并由 `_render_command_*_template` 进行 shell-quote 安全替换，`{{`/`}}` 保留为字面量。
- 命令型 provider 超时后通过 `_terminate_command_*_process_tree` 递归终止进程树（Windows 用 `taskkill /F /T`，Unix 用 psutil children），防止僵尸子进程泄漏。
- TTS 与 STT 提供商均以集合常量（`BUILTIN_TTS_PROVIDERS`、`BUILTIN_STT_PROVIDERS`）声明内置名，非白名单名称一律走命令型或插件分发路径，防止同名覆盖。
- 流式音频提供者实现统一的 `StreamingTTSProvider` ABC，通过 `@register(name)` 装饰器注册到模块级 `_REGISTRY`，并由 `resolve_streaming_provider` 按优先级（elevenlabs → gemini → openai → xai）或 `tts.streaming.provider` 配置解析。
