本模块由四个职责互补的子文件组成，围绕“配置加载 → 提供商选择 → 执行”的统一模式组织：
- `tts_tool.py` 是核心入口，集中管理所有 TTS 提供商（edge、elevenlabs、openai、minimax、xai、mistral、gemini、neutts、kittentts、piper、deepinfra），通过 `BUILTIN_TTS_PROVIDERS` 白名单区分内置与用户自定义命令型 provider（`tts.providers.<name>: type: command`），使用 `_import_*` 惰性导入避免在无头环境崩溃；通过 `tools.tool_backend_helpers.resolve_provider_secret` 统一解析 API Key（config > env/.env > 凭证池）。输出格式按平台自动选择 Opus（Telegram/Matrix/WhatsApp/Signal）或 MP3。
- `tts_streaming.py` 定义 `StreamingTTSProvider` ABC 与 `@register` 注册表，实现 ElevenLabs、OpenAI、Gemini、xAI 的流式 PCM 提供者，并通过 `SentenceChunker` 对 LLM token delta 做句子切分；与 `tts_tool.py` 共享配置读取和密钥解析。
- `transcription_tools.py` 以相同架构提供 STT：内置 provider（local/local_command/groq/openai/mistral/xai/elevenlabs/deepinfra）+ 命令型 provider 注册表 + 插件分发，维护全局 faster-whisper 模型单例并用空闲卸载线程释放显存；通过 ffmpeg 将任意音频转码为 16kHz 单声道 m4a 上传云端。
- `wake_word.py` 实现三引擎唤醒词检测（openWakeWord/sherpa-onnx/Porcupine），抽象为 `_Engine` 接口，统一 16kHz int16 帧输入，支持多 profile 短语注册与自动推理框架选择（macOS ARM64 强制 tflite）。
- `tts_text_normalize.py` 提供纯文本预处理管线：`strip_nonspoken_blocks` → `strip_markdown_for_tts` → `normalize_symbols_for_tts` → `smooth_whitespace_for_tts` → `flatten_newlines_for_payload`，最终产出适合朗读的单行脚本。
- `neutts_synth.py` 作为独立子进程入口，被 `tts_tool.py` 通过 subprocess 调用以隔离 ~500MB NeuTTS 模型内存。
依赖方向单向：`tts_streaming` 依赖 `tts_tool` 的配置函数；`wake_word` 反向探测 `tts_tool`/`transcription_tools` 的能力；各模块均不互相直接 import 业务逻辑，仅通过配置键约定耦合。
