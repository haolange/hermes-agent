本模块由四个相互独立的工具文件组成，分别承担不同职责并通过 `tools.registry` 对外暴露：
- `cronjob_tools.py`：定时任务工具入口，封装对 `cron.jobs`、`cron.scheduler` 的调用，实现创建/更新/暂停/恢复/删除/立即运行 cron job 的统一 API；内置双层 prompt 安全扫描（严格模式用于用户输入，宽松模式用于附带 skill 内容），通过正则匹配注入指令、敏感变量外泄、不可见 Unicode 等威胁，并限制脚本路径在 `~/.hermes/scripts/` 内、校验 `base_url` 覆盖不得泄露存储凭据；手动 `run` 走 `_execute_job_now` → `_run_claimed_job` 共享执行体，支持后台异步委派（`dispatch_async_delegation`）并在长时间运行时向父进程 activity tracker 发心跳以避免 gateway watchdog 误杀。
- `voice_mode.py`：CLI 语音模式，抽象出 `AudioRecorder`（基于 sounddevice + numpy 实时录音、RMS 静音检测、自动停止）和 `TermuxAudioRecorder`（Android Termux:API 回调式录音），统一输出 WAV/AAC；提供 beep/thinking sound 提示音、macOS afplay 回退、PulseAudio/PipeWire 可达性探测、SSH/Docker/WSL/Termux 环境检测，所有音频库采用函数内延迟导入以兼容无头环境。
- `clarify_tool.py`：平台无关的澄清问答工具定义，负责参数校验、choices 扁平化、多选型响应解析，并通过可选 `callback` 委托给上层平台实现；注册到 `tools.registry` 暴露 `clarify` 工具及 OpenAI Function-Calling schema。
- `clarify_gateway.py`：gateway 侧澄清原语，维护模块级 `_entries` / `_session_index` 字典与 `threading.Event`，实现 `register` → `wait_for_response`（带活动心跳轮询避免挂死）→ `resolve_gateway_clarify` 的阻塞等待-唤醒协议，并提供文本回复强制解析（数字序号/精确标签/多选 JSON）与超时配置读取。
依赖方向单向：`clarify_tool` 仅依赖 `tools.registry`；`clarify_gateway` 被 gateway 适配器调用；`cronjob_tools` 依赖 `cron.*` 与 `gateway.session_context`；`voice_mode` 仅依赖 CLI 层，不反向依赖其他工具。
