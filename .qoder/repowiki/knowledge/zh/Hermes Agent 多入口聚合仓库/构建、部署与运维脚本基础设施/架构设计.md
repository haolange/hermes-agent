本模块是项目的基础设施层，按职责划分为四个子目录：
- `scripts/`：一次性或可复用的运维脚本集合，包括多平台安装器（`install.sh`/`install.ps1`/`install.cmd`）、CI 辅助工具（`ci/` 下的评审注释、E2E 截图状态、锁文件差异分析等）、沙箱代理（`sandbox/proxy.py`、`ssh-shim.sh`）、WhatsApp 桥接服务（独立 Node.js 包 `whatsapp-bridge/`）以及各类观测、基准测试和诊断脚本。
- `docker/`：基于 s6-overlay 的容器运行时，入口点通过 `entrypoint-dispatch.sh` 判断是否为 PID 1，在 PID 1 路径下委托给 `/init` 启动 s6 监督树，非 PID 1 路径则直接执行 `stage2-hook.sh` + `main-wrapper.sh`；`cont-init.d/` 与 `s6-rc.d/` 分别负责初始化阶段和服务编排（dashboard、main-hermes、user）。`entrypoint.sh` 作为向后兼容的废弃 shim 仅转发到 stage2 hook。
- `nix/`：使用 flake + uv2nix/pyproject-nix 构建 Python 虚拟环境，并通过 `packages.nix` 暴露 `minimal`/`full`/`messaging`/`tui`/`web`/`desktop`/`sandbox` 等多个派生包；`devShell.nix` 聚合所有 npm workspace 的 `package.json` 并注入 Playwright、cage、ghostty 等 E2E 依赖；各 `.nix` 文件通过 `callPackage` 组合，将 skills、plugins、locales、optional-mcps 以符号链接形式嵌入 store。
- `.github/workflows/`：定义完整的 CI 流水线，涵盖 lint、tests、js-tests、e2e-desktop、install-e2e、docker-lint、supply-chain-audit、osv-scanner、skills-index、uv-lockfile-check 等任务，配合 `scripts/ci/` 中的 Python 工具产出评审注释与证据。
依赖方向：CI 工作流调用 `scripts/` 中的工具；`docker/` 在镜像内复用 `scripts/install.sh` 安装产物；`nix/` 提供本地开发与 NixOS 模块；三者共同构成从源码到运行时的完整交付链。
