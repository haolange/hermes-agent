模块以 `scheduler.py` 中的 `tick()` 为核心入口，由 gateway 进程内每 60 秒的后台线程驱动；通过 `scheduler_provider.py` 暴露 `CronScheduler` ABC 抽象触发器（默认 `InProcessCronScheduler` 实现内置 ticker，同时支持外部插件 `plugins.cron_providers` 替换），将“何时触发”与“如何执行”解耦。

内部分层清晰：
- 存储层：`jobs.py` 用 JSON (`~/.hermes/cron/jobs.json`) + 跨进程 `.jobs.lock` (fcntl/msvcrt) 维护作业元数据，配合 `use_cron_store()` ContextVar 实现 per-profile 隔离；`executions.py` 用 SQLite (`executions.db`) 记录每次尝试的生命周期（claimed→running→completed/failed/unknown）；`notepad.py` 提供 per-job KV 持久便签。
- 调度层：`scheduler.py` 维护两个线程池——并行池 `_parallel_pool` 跑普通作业、单线程池 `_sequential_pool` 串行执行会修改 `os.environ["TERMINAL_CWD"]` 的作业，并通过自实现的 `_ReadWriteLock` 保证 workdir 互斥；使用文件锁 `~/.hermes/cron/.tick.lock` 防止多进程重复 tick。
- 安全层：`lifecycle_guard.py` 在作业创建时扫描 prompt/script 中是否包含 `hermes gateway restart|stop`、`launchctl submit/bootstrap hermes-gateway`、`systemctl ... hermes-gateway`、`p?kill ... hermes.*gateway` 等模式，阻止 agent 自我重启导致 SIGTERM-respawn 循环。
- 扩展能力：`monitor.py` 提供 monitor_script/monitor_url 变更检测（哈希对比 + unified diff 注入 prompt）；`blueprint_catalog.py` / `suggestion_catalog.py` 定义参数化自动化模板与开箱即用建议，统一产出 `create_job` kwargs。
- 依赖方向：scheduler → jobs/executions/lifecycle_guard/monitor；provider → scheduler；catalog/suggestions 仅消费 jobs API；所有持久化均通过 `get_hermes_home()` 解析到当前 profile 目录，避免跨 profile 泄漏。
