- 每个 Electron 模块文件都配有同名 `.test.ts` 单元测试（如 `backend-health.ts` ↔ `backend-health.test.ts`），形成一一对应的测试组织方式。
- 平台差异通过独立的 `windows-*`、`wsl-*`、`bootstrap-platform.ts` 等文件封装，主入口仅做条件分发而非内联 platform checks。
- 配置与持久化状态统一写入 `app.getPath('userData')` 下的 JSON 文件（如 `connection.json`、`updates.json`、`window-state.json`、`native-theme.json`），并提供 read/write 成对函数。
- 共享类型与协议集中在 `apps/shared`，通过 `package.json` 的 `exports` 子路径导出，避免在 desktop 与 installer 中重复定义接口。
- 构建脚本集中在 `apps/desktop/scripts/` 下，以 `.mjs` 模块化脚本形式实现 before/after pack、bundle、notarize、perf 等阶段，并通过 `package.json` 的 `build.*` 钩子串联。
- 日志与诊断通过统一的 `desktop.log` 滚动策略（固定最大字节数 + 备份计数 + 丢弃阈值）进行落盘，避免崩溃循环撑爆磁盘。
